## rev60 样文沉淀（2026-11-03，Agent 权限篇）

- **例子控制参数变形 + 为什么**：抽象机制句后接"同一动作、参数变形导致风险跃迁"的具体例子。安全正例用参数被偷换（人批的是发邮件给 a@test.com，点确认和真正执行之间某层被注入，收件人变成全公司通讯录——没有执行前重验就直接发出），来源 A [A47]。A [A42]"删 test.log → 改删生产配置.conf"是 edit 从低风险进入的因果例，仅作风格参考，不推荐作技术正例（edit 回硬权限的因果链在本篇未充分展开）。
- **术语先中文定义再例子**：原文 A [A21] 逐字"不可逆的：动作能不能撤销。比如删除、覆写、对外发出的消息，做完了不能撤回"。不堆英文 token 对照。

- **本样文删判定 emoji，今后按需使用**：A 全文 56 段无一处 ❌/✅ 判断，1️⃣–6️⃣ 完整保留。这是 A 的选择，不是全禁 emoji 的规则；✅/❌ 在正反对照确实需要时仍可用，且带完整主语和理由。
- **旁支下沉教材**：RBAC 拆题、确认界面四件事、模型自评答法、幂等三步、Anthropic 引用、60 秒速答骨架在 1500 发布稿中不硬塞；判断标准是"是否解释当前主问题"。这不等于全局删除这些主题——教材可保留，正文按字数预算取舍。
- **结尾轻互动可选（样文观察，非全局规则）**：A [A56] 原文"关于 Agent 权限问题，欢迎深入交流～"。A 没收金句、没收 60 秒速答骨架；这不强制今后正文都不许留答题骨架或金句——帮助读者答题的骨架在合适形态下可保留，只是不硬套结尾、不与轻互动叠加。
- **不写作者元说明**：图面与正文不出现「我归纳的」「我判断的」；不出现「备考教学案例，非真实大厂题库」等免责声明。

## 可继承的表达

- 标题直接提出面试问题；封面先给机制图，正文分章节逐步展开。
- 中文讲述中保留 Agent、Memory、context、task spec 等业内词，必要处括注。
- 从边界与定位进入，再讲处理流程，随后交代故障与验证。
- 内容图多为白底黑字、少量色条；封面则米白纸纹、手绘框线、大标题、分色关系图。
- 结尾保持简短交流入口。本文参考的仅是这些组织方式，不复刻全文，不复制其“真实经历”身份。

## 不可继承的技术断言

样例正文包含需要重新核验的绝对化表达。例如“语义记忆无条件加载”“RAG语料本身可信”“重试全在Manager”“单Agent只能用一个最强模型”“无显著提升即负收益”，不能作为新教材依据。

## 用户改稿复盘：Reflection 是什么（2026-09-20）

本技能首次产出的发布稿经用户逐段改写后定稿。差异不在观点或事实——用户几乎未改任何技术论断——全部集中在**呈现形态**。以下为可复用的修正方向。

### 改动清单

| 维度 | 初版（我的） | 定稿（用户的） |
|---|---|---|
| 正文字符数 | 1499 | 约 1827 |
| 章节数 | 6 节 | 7 节 |
| 枚举呈现 | 四环节写成叙述段落 | 逐条拆行，`1️⃣`—`4️⃣` 编号 |
| 正反判定 | 「反思有效／无效」写在句中 | 独立成行，`✅` / `❌` 起头 |
| 代价一节 | 一段话带过时延成本 | 拆成 5 条独立编号 |
| 开篇 | 「不是让模型再想一遍」+ 核心判断两段 | 直接进「一、概念层级别搞错」 |
| 结尾 | 一句 CTA | CTA + 「欢迎多交流」 |
| 标签/来源 | 单列在正文后 | 全部删除 |

### 应当吸取的判断

1. **小红书是竖屏滑动阅读，不是文档阅读。**成列信息合并成段落会让读者失去计数感、无法回扫，直接被划走。凡是本就成列的内容（环节、控制点、形态、代价、原则），一律拆行编号。

2. **emoji 编号是平台语法，不是装饰。**`1️⃣2️⃣3️⃣` 与 `✅❌` 在小红书承担序号和判定功能，等同于文档里的有序列表和正反标记。此前把「不用 emoji」的通用规范套到发布稿上，判断错了。

3. **字数上限不该压过可读性。**初版为了卡进 1500 字，反复做了十余次微量删字（删「的」「得多」「完全」），既没有提升信息密度，又挤掉了排版空间。正确顺序是：先按 1000—1500 字定内容骨架，再排版，排版带来的字符增长属于正常成本。

4. **发布稿不需要铺垫段。**初版开头用两段做钩子和总判断，用户直接删掉，从第一个小标题进入。小红书读者是被封面和标题带进来的，正文不必再重复一次总起。

5. **标签和参考来源不进正文文档。**用户发布时另行处理，正文文档只保留可直接粘贴的部分。

### 不变的部分

技术论断、案例、术语括注、CTA 口径全部保留，说明内容层的判断标准是对的，只需修正呈现层。后续复盘若出现内容层改动，应单独记录，不要与形态问题混在一起。

## 用户改稿复盘：如何做 Agent 的评测（2026-09-20，第二次）

上一条复盘的教训执行到位了——拆行、emoji 编号、✅/❌ 判定、两步字数口径都做了。但用户仍从 rev 6 改到 rev 171。**这次的问题不是没排版，而是排版时把内容压过头了。**

### 改动清单

| 维度 | 我的 rev 6 | 用户定稿 rev 171 |
|---|---|---|
| 正文字符数 | 1596 | 2184 |
| 章节数 | 7 节（h2） | 6 节（h1） |
| 枚举条目形态 | 多数只有标签行 | 标签行 + 1—3 句解释 |
| `✅` 条目 | `✅ F3 → 上 schema 校验` | `✅ F3 参数问题 → 要上 schema 校验` |
| 三层检查 | 每层一句 | 每层补「这一层抓什么、为什么最硬/最容易漏」 |
| 稳定错 vs 抖动错 | 两行 ✅/❌ 对照 | 拆成 `<ul><li>`，每条讲清成因（温度、上下文顺序、表述变化） |
| pass^k 定义 | 「k 次全成功的概率」 | 补读法、补「再在所有任务上取平均」 |
| 建集一节 | 5 条要点，每条一行 | 7 条，每条带解释；F1—F5 触发条件另用 `<ul>` 展开 |
| 环境可复现 | 「时间字段写相对值」 | 补温度具体取值（Agent 侧 0，用户模拟器 1）与理由 |
| 归因表维护 | 未写 | 新增一条：看分布变化不看总数，举 F3 40%→10% / F5 10%→35% |
| 加粗 | 仅三层检查标题 | 15 处，落在每节核心判断 |
| 术语英文 | 无 | 「首次偏离点（first deviation）」「pass^k（读作 pass hat k）」 |
| 文档结构 | 发布信息表 + 封面 + 正文 + 数据来源 | 封面 + 正文 |
| 开篇 | 三段铺垫（78%／22%／总分） | 全删，直接进「一、」 |

### 应当吸取的判断

1. **压缩的对象是旁支和重复，不是论证本身。**我把「三层检查」每层压成一句、把稳定错/抖动错压成两行对照，读者拿到的是标签不是理解。用户全部补回解释。**留不住解释的压缩是失败的压缩。**

2. **`1️⃣` 后面不是终点，是开头。**枚举条目的正确形态是「标签行 + 解释行」，一条写到三四行完全正常。上一版规范里「每条控制在两行以内」这条写错了，已删除——它和「拆行编号」一起执行时，会把内容挤成名词表。

3. **`✅`/`❌` 要带完整主语和理由。**`✅ F3 → schema 校验` 读者扫到这里已经不记得 F3 指什么。写成 `✅ F3 参数问题 → 要上 schema 校验`。

4. **字数上限连续两次定低了。**第一次 1500 不够，改到 1800；这次用户仍写到 2184。现已改为骨架 1200—1700、成稿 2400。**判断依据是「每一行是否都在推进论证」，不是字符数。**

5. **专业度体现在具体值和长期用法上。**用户补了温度取值、τ-bench 跑 40 次做标注质检、归因表看分布变化——这些是「真做过」的信号。方法论类主题必须补一条「怎么长期维护」。

6. **术语要给英文/读法。**学生要靠这个搜原文。

7. **发布稿文档不是交付说明书。**我加的「发布信息」元信息表和「数据来源」节被全删——作者是全选复制去发的，中间夹的表格都要手动删。这些进 `release-review.md`。

8. **用飞书原生结构。**用户把并列项改成 `<ul><li>`，章节标题从 `h2` 提到 `h1`，加了 15 处 `<b>`。连续堆 `<p>` 在飞书里读起来是一片平文。

9. **开篇铺垫又一次被删。**上次已记过这条，我这次仍写了三段。**发布稿第一行就是第一个小标题。**

### 反复出现的模式

两次复盘都指向同一件事：**我倾向于把规范当成上限去卡，而用户要的是把内容讲透。**第一次表现为不敢拆行（怕超字数），第二次表现为拆了行但不敢写解释（还是怕超字数）。执行新规范时，先确认「这一行在推进论证吗」，再看字数；字数只在超过 2400 时才作为触发条件，用来回头删旁支或减章节。
