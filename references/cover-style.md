# 手绘技术图规范（封面与教材图）

## 手绘是硬性要求，不是可选风格

用户已明确：**所有配图都要有手绘感**。规整的矩形加直线箭头被判定为「丑」，不可交付。手绘感由三部分共同构成，缺一不可：

1. **框线抖动**：矩形、菱形的每条边都是带随机偏移的贝塞尔曲线，重描两遍（第二遍降低不透明度），边角略微出头。
2. **箭头手绘**：连线同样抖动，箭头用两笔短线自己画，**不要用 SVG `<marker>`**——marker 是规整三角形，一眼看出是机器画的。
3. **手写字体**：英文单词、数字、百分比必须用手写体，不能和中文一样用规整无衬线体。

## 封面是"全文总结图"，不是吸睛海报或标题配图

封面必须让学生**光看封面集合就能复述出完整答案**：单页时看这一张；双页时按 ①→② 顺序看合起来的两张。它覆盖全文核心：主问题与核心判断、核心模块及关系、主要机制或路径、工程取舍/参数/关键结论、重要失败分支及边界——具体主题没有的项写 `coverage_na` 理由，不凭空造参数或失败。

- 从真实教材核心章节 + 压缩正文逐点提炼 core_points，每个点标来源位置与图上落点（node/region）；双页时另标 `page`（0/1）；**不能先画好图再自己填点当自证**。
- 流程类主题：完整链路 + **失败分支**（哪一步断、重试/降级/中止各条路的结果）。
- 概念框架类：分区/分组表达模块关系，不硬画流程；失败与边界画成专门区域。
- 混合类：流程主干 + 框架分区。
- 底部一句适用边界（用本篇自己核实的条件，不套用旧示例的具体结论）；双页时两页各自页脚或末页统一收一句边界。

不要只画 happy path 不画失败——面试最易被追问的就是"失败了怎么办"。

对外配图 = **1—2 个封面单元**：默认 1 张；封面不是知识图轮播，不逐张出知识卡。仅当单图提炼层次后仍密度不可读时，才允许拆成 **2 张并列分块**（规则见下文「封面数量与双页规则」）；教材内部插图按教学需要可多图拆分，见下文「封面与教材图分工」。

## 本技能自带的手绘工具

`scripts/sketch.py` 是零依赖的手绘 SVG 生成器，用标准库 `random` + `math` 实现，不需要 rough.js。

用法：

```python
import sys
sys.path.insert(0, "<技能 scripts 目录的绝对路径>")
from sketch import Sketch

s = Sketch(seed=20260920)   # 固定种子，同一张图可复现
s.rect(x, y, w, h, stroke="#B8382A", fill="#FBEBE8", width=2.8, rough=2.2)
s.diamond(cx, cy, w, h, stroke="#C9762B", fill="#FBEFD9", width=3.4, rough=2.6)
s.arrow(x1, y1, x2, y2, stroke="#2E2A26", width=2.8)
s.curve_arrow([(x1,y1), (x2,y2), (x3,y3)], stroke="#2F7A55")   # 折线箭头
s.underline(x1, x2, y, stroke="#C9762B")                        # 标题手绘双下划线
s.line(x1, y1, x2, y2, passes=1)                                # 单笔分隔线
```

每个方法返回 SVG 片段字符串，拼进 `<svg>` 即可。`rough` 参数控制抖动幅度，框 2.2、菱形 2.6、连线 1.8 是实测好看的值。

流程：写一个 `build_cover.py` 生成 HTML，再用 Chromium headless 截图。源码留在该篇项目目录，便于逐处微调。

## 字体

环境实测可用（不要臆造其他字体已安装）：

| 用途 | 字体 | 说明 |
|---|---|---|
| 英文、数字、百分比 | `Purisa` | 泰文字体，拉丁部分手写感最强，实测最佳 |
| 备选手写英文 | `Chilanka` | 比 Purisa 略工整 |
| 中文全部文字 | `Noto Sans CJK SC` | 思源黑体，环境中最接近苹方（PingFang SC）的可用字体 |

**关于苹方**：`PingFang SC` 是苹果专有字体，只随 macOS / iOS 分发，Linux 环境无法合法安装。CSS 可写成 `"Noto Sans CJK SC","PingFang SC"` 作为回退声明，但实际渲染用的是思源黑体——两者同属现代无衬线黑体，字形接近。**不要声称已使用苹方。**

混排写法：中文用思源黑体打底，英文片段用 `<tspan font-family="Purisa">` 包起来。

```python
def hand(t):
    return f'<tspan font-family="Purisa">{t}</tspan>'

# 用法：f'<text ...>首轮通过率 {hand("95%")} 时</text>'
```

标题里的英文（如 Reflection、LangGraph、RAG）也要包，这是手绘感最显眼的地方。中文黑体配英文手写体的反差本身就是风格的一部分，不要为了统一把英文也改成黑体。

## 默认规格

- **尺寸硬约束（竖版 3:4）**：每个封面单元都是竖版，宽:高 = **3:4**，参考尺寸 **1080×1440（宽 1080、高 1440）**；预览默认 PNG，格式可换，更高分辨率按同比例放大（如 1620×2160），字体/线宽/边距一起放大。**不允许横版 4:3（1440×1080）或其他比例**；manifest 必填 `canvas: {"ratio": "3:4", "width": 1080, "height": 1440}`，脚本按 height ≈ width×4/3（±1%）且 height > width 校验，渲染导出像素必须与声明一致。
- 背景为暖米白轻纸纹（`#FAF6EE` + 径向渐变颗粒）；标题深黑（`#2E2A26`），配手绘双下划线。
- 框线抖动但**内容几何位置与箭头端点仍要精确**；固定随机种子保证可复现。
- 配色：琥珀 `#C9762B` 表达判断/关口，绿 `#2F7A55` 表达可行路径/事实，红 `#B8382A` 表达失败/不适用，灰 `#7A736A` 表达降级/中性。避免无意义多彩和大面积紫色。
- 标题建议 58—76px，节点标题 27—31px，正文标签 23—26px，安全边距约 56—64px；仅为初始设计值，实际字形/密度决定调整。不能为塞满缩到无法阅读。
- 上方主问题，下方是占主体的真实关系图，底部至多两三句适用边界。不要把整篇教材挤进封面。
- 采用较大字号与充分利用版面，减少无意义留白；读者应先看懂主标题和结构，再读细节。

## 封面数量与双页规则（1—2 个单元，并列分块）

**数量口径**：默认 1 个封面单元；0 个拒绝；2 个是上限，3 个及以上拒绝。双页仅在单页密度不可读时启用，不为追求"图多"而拆分。

**启用双页的判定（先压缩、后拆分）**：
1. 先按层次提炼节点、合并同义标签、简化连线；
2. 仍出现以下任一密度信号，才允许拆 2 页：节点标题/正文标签被压到低于可读下限、框体重叠、箭头交叉打结、安全边距被侵占、手机宽度下无法快速找到目标节点；
3. 拆分理由（哪些点、为何塞不下）与两页分工必须写进 `review.md` 与 cover-review 证据，不允许无理由双页。

**双页组织方式（并列分块，无总览页）**：
- 按主题切成两组，例如页①=主问题/核心判断/主干机制或框架，页②=参数取值与选型对比/失败分支/边界；分组以语义完整为准，不平均凑点。
- 页角或页标题标注 `①`、`②` 与本页副标题；两页共享同一主标题前缀（如"Agent Memory 设计（1/2）（2/2）"），保证读者知道是同一篇。
- **不画跨页长箭头**：跨页依赖用页内文字标注（如"失败档见②"），连线只在本页节点之间。
- 两页合起来必须覆盖全部 core_points；每个 core_point 的 `page` 字段标明落点；两页各自结构自洽（各自节点、边、图例可读），不是一页未完成内容的截断。
- 两页共用同一份 cover manifest、同一个 diagram_type 与同一套节点/边清单；一页偏流程、一页偏框架时选 mixed，不拆成两份 manifest 分别登记。
- 阅读顺序固定 ①→②；交付时按序排列文件与预览。

## 生成路径

先读取当前挂载的 visualization 与相关图片技能。在精确架构/数据流图场景，用 `sketch.py` 构建节点、文字和连线，再渲染导出图片。**手绘只作用于线条外观，不能由随机图像生成决定逻辑拓扑。**

若使用图生图保持纸纹、插画或视觉资产，按图片技能传入实际参考 URL；本地资产先上传。生成后所有事实文字与箭头必须逐项复核，必要时确定性排字覆盖。出图工具的 schema 以真实环境为准。

字体按本地实际可用性选择。不下载不明授权字体；使用可用的开源字体并保留所需许可。未找到字体时优先保持可读性，明示是否与样例不同，不伪称像素级复刻。

## 封面与教材图分工

教材图服务完整理解，可多图拆分；教材内嵌的 mermaid 画板不强制手绘（平台渲染不支持），但**封面必须手绘**。

封面提炼全文核心要点：主问题、核心判断、模块关系、机制路径、取舍/参数、失败分支与边界都要有落点，主题不适用的项写 coverage_na 理由；不为好看省略关键条件。封面不能把「推荐方案」画成「唯一路径」。

节点过多时先提炼层次，不盲目删节点或提高密度；提炼后仍不可读才按上文「封面数量与双页规则」拆 2 页并列分块，并记录拆分理由。不自动扩成 3 张及以上内容卡，也不把教材内部插图混进对外封面集合。

## 验收

1. 先跑 manifest 结构检查（含封面单元数量 1—2、canvas 竖版 3:4、双页 page 标注），再用正常/失败/人工介入分支（如有）逐页走图。
2. 实际打开渲染后的完整 PNG；如果截图视口影响底部，扩大视口并按完整画布导出，不能裁掉正文。**核对导出像素为竖版 3:4（如 1080×1440），与 manifest `canvas` 声明一致；横版或比例漂移返工。**
3. **逐项检查手绘特征**：框线是否有抖动、箭头是否是手绘两笔而非 marker 三角、英文数字是否用了手写体。三项缺一都要返工。
4. **检查标签与框的重叠**：手绘线条比规整线条粗且有偏移，边缘标签容易压到相邻方框。每个连线标签都要单独看一遍。
5. 以手机宽度检查字、线、配色和阅读顺序；找不到目标节点、箭头方向不明、字压在线上都要修。双页时分别检查两页，并确认 ①→② 顺序与跨页文字指引清楚。
6. 与原始文案逐一核对专名、数字和标签；用独立的文字清单避免删词导致逻辑变化。双页时按 core_points 全集逐点核对落点（含 page 标注），不允许某页只画了半套逻辑。
7. 最终交付**可修改形式**：每个封面单元 = 可编辑源文件 + 预览产物（manifest 里 `covers: [{source, preview}, ...]`，1—2 项；单张兼容 `cover: {source, preview}`），不硬锁 SVG/PNG/PPTX 任一格式；编辑源与生成脚本留在该篇项目目录用于后续单独修改。勿把截图验证中间件或历史参考图当成新的封面交付。
