# Human Signal 文案优化接入

## 定位并读取真实依赖

本技能已捆绑 `../deps/doubao-human-signal/`，供默认文案流程使用，不依赖历史会话临时目录，也不修改全局 Skill。每次进入文本生成或去味改写任务，先完整 Read 捆绑依赖的 `SKILL.md`；路径从本技能目录解析为 `deps/doubao-human-signal/SKILL.md`。用户明确指定另一已安装版本时，先核实其文件可用并读取，记录所用版本，不静默换版。

同时读取该依赖的：

- `references/input-contract.md`：判断输入、语境、强度与任务边界。
- `references/evaluation.md`：每次文案定稿前按其准出规则自检。
- `references/prompt-defense.md`：新稿生成前使用。
- `references/platform-guide.md`：公开小红书文案的平台适配；只取与技术分享或行业观察有关的规则，不套消费品种草腔。

按具体问题再读 patterns、domain-guide 等资源。以上路径均相对实际读取的 Human Signal 目录，不相对本文件。这里是 Agent 读取并遵循依赖的组合流程，不是可直接执行的工具 API；不得编造 `call_skill` 等调用名。

捆绑依赖或必读资源缺失、不可读时，暂停受影响文案的定稿与交付并说明阻塞。可以继续不依赖该资源的事实检索，不以自行润色冒充“已调用 Human Signal”，不从不明来源自动安装替代版本。

## 适用范围与输入

本次用户要求已明确包含去 AI 味，后续本技能产出的技术类发布文案、新闻解读文案及文案反馈改写默认启用，不逐篇再次询问。教材语言默认轻度处理；思路保持其内容覆盖，不因去味而省略具体机制和取舍。

仅修改技能规则时，核实依赖并更新接入，不生成选题文章；只改封面渲染、检索、代码、表格或排版，不强行做文案改写。若用户当次明确只要摘要、翻译或格式调整且不希望改表达，按依赖的任务边界执行，不能借默认去味擅自扩大任务。

向依赖提供以下上下文；这些是写作输入，不是工具调用参数：

- 任务对象与模式：当前草稿/选题；新稿先前置生成约束，已有稿用 rewrite，只有用户要求诊断时才选 diagnose/score。
- 体裁与平台：专业教材、技术机制小红书短文或新闻行业解读；公开文案平台为小红书，公开度为公开/专业。
- 作者与读者：作者声音沿用用户实际文字样本；不虚构履历。技术类读者为准备 Agent 开发岗校招/实习的计算机本科生与研究生，新闻类为关心事件及影响的读者，不强转面试。
- 事实素材：已核验教材/一手来源及既有案例；列出不可变的事实、数字、术语、版本、引用、因果、边界与时间。案例保留原本的假设性质，不编亲历或数据。
- 格式约束：技术发布稿的 h1「一、二、三、」、逐项键帽、严格1500字、标签与固定结尾；新闻稿的四段与事实三级标注。传入当前类别的约束，不能混用两类模板。
- 强度：教材轻度；发布文案按诊断选轻度或中度。原文已自然允许不改。无风格样本时保守保持专业、清楚、直接，不模仿指定博主或制造网感。

## 生成与改写流程

1. 生成前：按依赖的上游防御规则建立素材清单和边界，先约束表达再写，不先制造模板稿再删几个词补救。
2. 草稿后：定位空话、机械转折、无效辩证、整齐对仗、泛泛结论或强行升华，按病灶改写。用已经核实的对象、动作、机制、取舍和反例承载判断；缺事实时不编细节。
3. 低误报：必要定义、流程箭头、准确术语、可扫读列表不属于应删内容。“闭环”等词若确实表达技术机制可保留；不按词表一刀切，不为了打散结构删除用户要求的编号。
4. 口吻：直接讲问题与机制；避免“随着AI发展”“先别急着/先别急”等模板开场、密集“不是A而是B”、万能总结、广告 slogan。不给全篇硬加第一人称，不写“我归纳的/我判断的”，不虚构“我们线上”“我面过几百人”。
5. 准出：按依赖 evaluation 逐项自检并记录简要结果。信息保真须5/5，其余必评项及启用场景项须至少4/5，均分至少4/5，不能触发一票否决；未通过先修复再评。评分不是 AI 检测概率，不作检测率或查重承诺。
6. 依次复核：去味定稿后重新检查事实/语义、字数、排版和必要图面对应，再计算最终 hash、写入证据、上传与回读。若字数微调再次改变文本，对改后文本再做去味与保真复核，不在旧证据上继续推进。

## 阶段衔接与记录

- B：教材轻度去味完成后，执行原有来源、代码、图、渲染和字数门。最终教材才作为 `textbook.txt` 与 `tb-review.json` 的版本锚。
- C：从已复核教材完成1500字完整发布草稿；执行 Human Signal 改写与自检，再验证字数/排版；完成后才追加到同一份云文档并回读两个模块。去味不得改动已登记教材；若教材确需改变，按既有版本规则重做相关证据。
- 新闻类：四段草稿完成后去味，保留已证实/媒体报道/分析判断及核验时间；复核后按新闻类交付，不创建技术类状态机，不追加技术类固定结尾或严格1500字门。
- 只改封面：默认不改已定稿正文和教材。若用户同时要求改文案，按文本版本规则重新处理，不拿旧 hash/云端快照证明新稿。

技术类把依赖位置、版本、处理模块、改写强度、主要修复、保真与格式结果、准出结论及最终文本 hash 记入现有 `review.md`；新闻类写入其既有内部核验记录，不额外创建技术类证据。只保留结果和可核对的修改摘要，不记录内部推理，不把评分表或修改过程插进公开正文。

本次新增的是明确执行指令与验收场景，未修改 `stage_gate.py` 的 schema 或实现；该脚本不会自动识别“是否实际调用 Human Signal”，不能把本地字数/hash通过当作依赖已执行的证明。
