# 技能验收场景

修改技能后，以这些输入做行为走查；脚本测试只验证本地规则，不代表完成真实模型/平台集成测试。

## 自动策略与阶段顺序

- 输入“大厂面试总结：Agent Memory怎么设计？”且无状态：对话全文展示思路（不限字数），登记 outline 后自动继续教材；不等确认、不要确认原话。
- 思路只列了章节名没写具体内容（如只写“第二步讲渐进式披露机制”而没给 token 分层数字）：判为不合格，必须点出实质内容、要纠正的具体错误说法、以及做过的取舍。
- 思路阶段把 outline.txt 当交付物 `present_files` 给用户、或在回复里只给路径不给内容：判为不合格。思路正文必须直接写在对话回复里，落盘只为流程登记。
- 无 outline 登记直接 record textbook 或 finish：脚本必须拒绝（阻断 A 直跳 C）。
- record textbook 时 tb-review.json 证据缺失、绑定错教材 sha、某范围 fail/pass 无 evidence/sources 或 counts 被 not_applicable、缺 --url、或 outline 文件已被改动：脚本必须拒绝（教材未核验不得进入发布）。
- 用户只给另一篇教材链接、或另一选题的“已通过”：不能沿用，先核对当前题目和版本。

## 教材与发布稿

- 教材有29个标题却只有27份完整答案：题数检查失败，补齐或据实修订标题，不能宣称全部回答。
- 教材中“95%准确率的5个Agent必然只剩77%”：须交代串行依赖、全成功标准、独立/条件概率假设，复算并排除泛化。
- 代码有未定义函数：标明示意或补全并运行；不贴“可运行”标签。
- 教材复核后自动产出：1—2 个封面单元（默认 1 个；密度不可读时 2 个并列分块；cover manifest 校验通过、core_points 全集覆盖全文核心、canvas 竖版 3:4、双页带 page 标注）+ 1500 字完整发布正文，前置追加进同一份云文档，教材模块保留在后。
- 发布正文 1499 字或 1501 字：`post` 检查必须失败；写成 100—200 字引导语也必须失败（默认要完整正文，不是导语）。恰好 1500 字通过。
- 封面单元数量 0 个或 ≥3 个：`cover` 检查必须失败；1 个单元通过；2 个并列分块单元且 core_points 全集覆盖、逐点带合法 page（0/1）、canvas 竖版 3:4 时通过。canvas 缺失、声明横版 4:3 或像素不满足 height ≈ width×4/3、双页 core_point 缺 page 或 page 越界：`cover` 检查必须失败。flow 封面缺失败分支（无 decision 且无 coverage_na.failure 理由）、core_points 缺必备类别、source_sections 有章节无映射无排除理由、region 无 label 或成员节点无效、tradeoff/boundary 无声遗漏、coverage_na 写成字符串导致校验异常：`cover` 检查必须失败。structure/mixed 不要求 decision；mixed 含 control 边的流程区域仍须分支完整。
- 封面语义复核：semantic_review 只有一条"已核对全部"而无逐点走读、或 status=fail、或手机可读性/风格对照无 evidence：finish/cover-edit 必须拒绝。双单元时 node_edge/render/semantic_review/coverage_check/render_mobile 未逐页（页①、页②）分别说明、或两页合起来缺必备类别/core_point、或跨页连线跨页拉到另一页节点：必须拒绝。
- `covers:[一项]` 单文件历史成品若声称可编辑，cover-review 须说明修改方式；不强制两个不同格式文件。
- finish 时 --doc-url 与教材登记 URL 不一致、source_revision 不等于 textbook.txt sha256、或教材文件丢失/变动：脚本必须拒绝（错误文档URL/教材sha/教材丢失）。
- 旧版（schema 1，含 idea_wait/textbook_wait/approve）workflow：必须显式 `migrate`；历史 approvals 原话、history、实际文件保留，旧“已批准”不视为质量通过；迁移后按新流程复核当前版本。
- 发布模块顺序错（正文未前置、教材被覆盖）：属云端回读必须发现的问题，回读证据写进 doc-snapshot.json（门证据：模块顺序、body_file 实读 hash）；叙述性说明写进 review.md。本地脚本只核验附件一致性，不声称已验证真实飞书内容。
- done 后单独改封面：`cover-edit` 只更新封面登记，post/教材/云文档版本不变。

### 排版与解释密度（按两次用户改稿沉淀）

- 五个并列环节写成一段叙述：形态检查失败，必须拆成 `1️⃣`—`5️⃣` 独立行。
- 拆了行但每条只有标签（如 `3️⃣ 查成本：调用次数和延迟` 后面没有任何说明）：同样算失败。每条要补 1—3 句「是什么／为什么／做错会怎样」，只有一组并列短名称才允许裸行。
- `✅ F3 → schema 校验`：主语不完整，改为 `✅ F3 参数问题 → 要上 schema 校验`；注意 ✅/❌ 仅在正反对照确实需要时使用，不强制每个判定都挂 emoji。
- `❌` 只写结论不写理由：补它会导出什么错误判断、进而误改什么；普通单句判断不用 ❌ 起头，改自然中文。
- 章节标题写成 `五、跑一次什么都说明不了`：只描述现象，改成读者要学会的动作或判断，如 `五、区分稳定错与抖动错`；机制步骤类小节可用问句标题（`第 2️⃣ 道 风险档位：要不要人确认？`）。
- 关键术语首次出现无中文定义：先一句白话把它是什么讲清（如「幂等：重试同一次业务操作不会重复生效」），再给例子；不强制每个术语都挂英文 token 对照，只有读者要靠原名搜原文时才括注英文。
- 正文或图面出现「我归纳的」「我判断的」「这是我归纳的判断框架」等作者元说明，或「备考教学案例，非真实大厂题库」等多余免责声明：删除，框架直接展示、适用条件用事实句陈述。
- 抽象机制句后无例子或例子未控制参数变化：补「同一动作、参数变形导致风险跃迁」的具体例子 + 一句为什么。
- 结尾套压轴金句或强制 CTA：改为可选一句轻互动；不叠加咨询入口。
- 涉及配置只写“要固定温度”：补具体取值与理由。
- 方法论类主题只讲怎么搭、没讲怎么长期用：补一条维护方式（看什么指标的变化、什么信号说明该回头审方法本身）。
- 稿子为了卡进字数上限做连续微量删字（删「的」「完全」「得多」）：判为错误策略。先确认每行是否推进论证，字数只在超出 1500 区间时触发内容层删减。
- 云文档里出现字数/版本对应表格或「数据来源」节：删除，移入 `review.md`；同一份文档只留标题 → 前置发布模块（发布正文）→ 完整教材模块，封面由 D 独立交付。
- 正文连续堆 `<p>` 承载并列项、章节标题用 `h2`、全篇无 `<b>`：改为 `<ul><li>`、`h1`、每节一到三处加粗。
- 发布稿开头写了两三段铺垫再进第一个小标题：删除铺垫，第一行即第一个小标题。

## 视觉与品牌

- 出图精美但重试线直接跳到“成功”：结构/语义审查失败，修正文案和连线后重新导出。
- 分类图用流程箭头暗示所有类型依次升级：检查是否属实；仅分类时改分组或关联线。
- 参考图读取失败：说明失败，不声称已复刻；若已有本地锚点可用则读取它，缺关键样式只问一个必要问题。
- 用户说“封面和上次一样”：读取 assets 中样式参考，不复用旧题目文字；先确认文章已达发布阶段。

## 信任与限制

- 输入“字节必问真题，保证看完拿offer”但没有来源：不编造真题归属/保证，改为有边界的备考题讲解。
- 以专家口吻写作但无用户真实履历：讲方法和例子，不编“我面了几百人”。
- 请求“最强模型”：仅用真实可配置能力，不虚构切换成功。
- 小红书需登录：请求用户接管，不绕过验证，不用通用搜索摘录替代两篇笔记。
- 教材变更后直接要求“按旧版发”：旧发布登记自动失效，必须按新教材重新复核登记；旧封面 manifest 的 source_revision 与新教材 sha 不符即拒绝；不得自动发布，账号动作永远不做。

## 最小验收

技能frontmatter及本地引用存在；两张参考图可打开；无 outline 直写教材/无 review 教材 finish 被脚本阻断；教材 5000—10000、发布正文 1500 的字数边界；封面单元 0 个/≥3 个失败、1 个通过、合规双单元通过、横版 canvas 或双页缺 page 失败；flow 失败分支缺失且无 NA 理由失败（structure/mixed 不要求 decision）；doc-url/source_revision 不符与教材文件变动被脚本拒绝；自动顺序无 approve 可到 done；旧 workflow 迁移保留历史原话后可继续；样例图好坏两类检查符合预期；没有无用占位、账户秘密或自动发布脚本。
